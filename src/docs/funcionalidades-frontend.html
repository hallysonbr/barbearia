Autenticação & Autorização

Fluxo de login, guard de rotas e controle de visibilidade

🔑 Login MOCKADO

Formulário reativo com validação inline de campos obrigatórios (e-mail válido + senha).

  • Credencial mockada: admin@barbearia.com / 123456
  • Token armazenado em localStorage como 'mock-token'
  • Feedback de erro inline: "E-mail ou senha inválidos"
  • Ao acessar /login, o usuário é sempre deslogado

🛡 Proteção de Rotas

Guard AuthGuard implementado com CanActivate.

  • Verifica isAuthenticated() via BehaviorSubject
  • Redireciona para /login se não autenticado
  • Rotas protegidas: /home, /services, /appointments, /users
  • Rota wildcard (**) redireciona para /login

👁 Diretiva de Visibilidade

Diretiva estrutural *appShowIfAuth controla exibição de elementos baseada no estado de autenticação.

  • Assina o isAuthenticated$ Observable do AuthService
  • Cria/remove a view dinamicamente via ViewContainerRef
  • Utilizada no <app-header> para ocultar navegação na página de login
  • Implementa ngOnDestroy para evitar memory leaks

🔄 Fluxo de Autenticação

/login → Valida credenciais → Armazena token → Navega /home
Logout → Remove token → Redireciona /login

⚠ Regras de Negócio Identificadas no Frontend

  • Autenticação: Login com e-mail + senha; token armazenado para sessão
  • Serviços: Cada serviço tem nome, descrição, preço e ícone

  • Agendamentos: Vinculam um serviço a um nome de cliente; ícone derivado do tipo de serviço
  • Dashboard: Contagens segmentadas por período (hoje, aguardando, amanhã)
  • Visualização: Dual-mode (cards/tabela) para listagens, com auto-switch responsivo
